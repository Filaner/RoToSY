01

시작 전

접속 주소 http://서버주소:8080/

통합 launch를 실행하면 웹 서버도 켜집니다. 웹 서버를 따로 켜지 마세요.

주의 · 실제 장치 연결

웹 서버를 켜면 카메라·센서·ROS2 bridge도 초기화됩니다.
mode:=virtual은 Doosan driver만 전환합니다. 전체 시스템의 가상 모드가 아닙니다.

설치와 실행

외부 driver와 장치 설정이 필요한 빌드 예시입니다. 아래 명령만으로 전체 환경이 갖춰지지는 않습니다.

필요한 환경

  • Ubuntu/Linux, ROS2 Humble, Python 3.10, colcon.
  • Doosan ROS2 driver의 dsr_bringup2, dsr_msgs2. 실장치는 E0509 연결과 전자석 그리퍼 배선이 필요합니다.
  • RealSense SDK, pyrealsense2, ArUco 지원 OpenCV. ROS2 카메라 보정에는 realsense2_camera가 필요합니다.
  • 웹 requirements.txt, OCR용 google-cloud-vision, PLC용 pymodbus. PLC 코드는 slave= 인자를 지원하는 버전이 필요합니다.
  • AMR: Gazebo Classic 11, gazebo_ros, nav2_bringup, turtlebot3_gazebo, turtlebot3_navigation2, robot_state_publisher. 카메라 뷰는 rqt_image_view를 사용합니다.

1. Workspace build — 장치 실행 없음

위 의존성을 먼저 준비하세요. 외부 driver를 별도 workspace에 설치했다면 해당 환경도 source합니다.

mkdir -p ~/rotosy_ws/src
cd ~/rotosy_ws/src
git clone https://github.com/Filaner/RoToSY.git
cd ~/rotosy_ws
source /opt/ros/humble/setup.bash
/usr/bin/python3 -m pip install -r src/RoToSY/hospital_web/backend/requirements.txt
colcon build --symlink-install
source install/setup.bash

통합 launch는 웹 서버에 /usr/bin/python3을 사용합니다. 위 pip 명령은 웹 requirements만 설치합니다. driver·RealSense·OCR·PLC 의존성, 모델과 인증은 별도 준비 항목입니다.

2. Integrated robot stack — 실장치 연결

모델·장치 설정을 마친 뒤 실행하세요. host와 plc_port는 실제 연결 정보로 바꿉니다.

실제 로봇·PLC 연결과 카메라 캡처를 시작합니다. 웹 조작과 작업 요청은 장치를 움직일 수 있습니다.

source /opt/ros/humble/setup.bash
source ~/rotosy_ws/install/setup.bash
ros2 launch doosan_controller robot_controller.launch.py \
  mode:=real host:=110.120.1.52 plc_port:=/dev/ttyUSB0

Doosan driver, PLC·arm controller, TCP monitor, 웹 서버와 작업 시퀀스가 함께 실행됩니다. 관리자 화면은 http://localhost:8080/입니다.

mode:=virtual은 Doosan driver에만 적용됩니다. PLC·카메라는 가상화하지 않습니다. Doosan 가상 driver 환경도 따로 준비해야 합니다.

3. AMR simulation — Gazebo 내 주행

별도 터미널에서 실행합니다. 로봇팔·PLC 통합 스택은 시작하지 않습니다.

source /opt/ros/humble/setup.bash
source ~/rotosy_ws/install/setup.bash
ros2 launch mobile_simulation mobile_simulation.launch.py
  • 기본값은 목표 요청 대기입니다. 단독 이동 데모는 auto_start_demo:=true를 추가합니다.
  • 웹과 연결하려면 DB의 병동 목표 좌표를 시뮬레이션 월드에 맞춥니다.
  • 화면 없이 실행하려면 show_gazebo_client:=false show_camera_view:=false를 추가합니다.
모델·장치 설정

보정값과 경유점은 특정 장치 배치를 전제로 합니다. 장치나 배치가 달라지면 다시 보정하세요.

항목준비 내용
YOLO weightsROTOSY_VISION_MODEL에 모델 경로를 지정합니다. 모델 로더는 backend/models/best.pt도 탐색합니다. weights는 저장소에 없습니다.
Camera extrinsic실측한 camera_extrinsic.yaml. ROTOSY_CALIBRATION_CONFIG_DIR로 디렉터리를 지정할 수 있습니다. 형식 예시를 참고하세요.
Cabinet calibration캐비닛 기하와 서랍별 TCP 보정. 설정 디렉터리는 ROTOSY_DOOSAN_CONFIG_DIR로 지정할 수 있습니다.
Robot / PLClaunch의 host, plc_port와 plc.yaml. 배선·국번·시리얼 통신 조건을 확인합니다.
Google CloudGOOGLE_APPLICATION_CREDENTIALS와 Cloud Vision 사용 권한. motion_sequence.py의 GOOGLE_PROJECT_ID 상수도 사용할 프로젝트에 맞춥니다.
작업·적재 데이터약품 치수·수량·서랍 설정, 배송 박스, 병동 좌표를 DB에 등록합니다. 시퀀스의 경유점과 박스 바닥 높이는 재측정합니다.
02

작업 순서

  1. 간호사
    처방 등록

    환자와 병동, 약품과 수량을 입력합니다.

  2. 약사
    처방 승인

    처방 내용을 확인합니다. 승인만으로 로봇이 움직이지는 않습니다.

  3. 간호사
    배송 요청

    승인된 처방에 배송을 요청합니다.

  4. 관리자
    오케스트레이터 시작

    장치 준비와 약품별 서랍 설정을 확인하고 작업을 시작합니다.

  5. 로봇팔
    집기 · OCR 검수 · 적재

    약품명이 처방과 같으면 박스에 적재합니다. 다르거나 확인할 수 없으면 컨베이어로 보내고 실패를 알립니다.

  6. 약사·관리자
    적재 확인

    전체 집기와 검수 결과를 확인합니다. 양쪽의 적재 확인이 끝나면 자동 출발을 요청합니다.

  7. AMR 시뮬레이션
    병동 이동 · 복귀

    병동에 도착하면 약재실로 복귀합니다. 현재 자동 경로는 수령 확인을 기다리지 않습니다.

주의 · 자동 작업과 수동 배송을 섞지 마세요

자동 배송은 병동으로 직행합니다. 수동 배송은 간호스테이션을 거칩니다.
두 방식을 섞으면 이동 목표와 상태 변경이 충돌할 수 있습니다.

03

시스템 연결

소프트웨어·데이터 실장치 연결 시뮬레이션 외부 Cloud API

OCR 호출은 로봇 시퀀스, 처방 대조는 웹 서버가 맡습니다.
motion_sequence가 웹의 원본 영상을 Cloud Vision에 보냅니다. 인식 결과는 웹 서버에 전달합니다.

05

상세 참고

AMR 배송은 시뮬레이션입니다. 실제 AMR 배송이나 병원 출입문 제어를 검증한 것은 아닙니다.

데모 조작도 DB와 장치에 영향을 줄 수 있습니다. 적재 확인 상태를 바꾸면 자동 출발을 요청할 수 있습니다. 초기화하면 기존 데이터를 지웁니다.

준비 데이터와 화면의 제한
  • 환자·병동·약품, 약품–서랍 매핑, 수량·치수, 배송 박스와 병동 좌표를 준비합니다. 서버 시작만으로 시연 데이터가 생기지는 않습니다.
  • demo_create.py는 DB에 데이터를 씁니다. --reset은 기존 도메인 데이터를 삭제합니다.
  • 복약 일정은 ?chart_no=환자번호로 지정합니다. 번호가 없으면 첫 환자를 보여줍니다. 미션과 최근 처방 목록 전체를 이 환자로 필터링하지는 않습니다.
  • 바코드 스캔은 샘플 문자열입니다. 이상 신고와 간호사 호출은 화면 문구만 바꾸며 알림을 보내지 않습니다.
  • 미리보기가 적재 완료를 뜻하지는 않습니다. 계획을 생성하면 DB가 바뀝니다.
  • 수동 배송 API는 CONFIRMED에서 간호스테이션으로 이동합니다. 간호사 수령 후 PICKED_UP을 기록하고 병동으로 출발합니다.
  • 적재 확인은 서버의 상태값입니다. 직접 이동·테스트 API까지 막는 인터록이나 사용자 인증은 아닙니다.
상태 표시와 저장 방식

웹 연결과 장치 연결은 다릅니다. 통합 상태는 /ws로 기본 10 Hz에 전달하며, 목록과 이력은 HTTP로도 조회합니다.

표시의미와 주의점
처방 awaiting_load_confirm집기 시작 시 설정됩니다. 집기 완료를 뜻하지 않습니다.
Orchestrator AWAITING_LOAD_CONFIRM전체 집기가 끝나고 적재 확인을 기다립니다.
미션 CONFIRMED두 적재 확인과 함께 can_dispatch를 결정합니다. 미션은 집기 전에 생성됩니다.
AMR ARRIVED정상 Nav2 경로에서는 goal 성공입니다. mock·데모는 주행 없이 상태를 바꿀 수 있습니다.
COMPLETED자동 경로에서는 약재실 복귀 시 기록됩니다. 실제 수령·투약을 검증한 결과가 아닙니다. 수동·데모 API로도 변경됩니다.
OCR MATCHED / MISMATCH / UNKNOWN약품명의 일치·불일치·확인 불가입니다. 용량과 수량까지 검증하지는 않습니다.

PLC 표시는 현재 DISCONNECTED로 고정됩니다. 인버터 명령 표시도 실제 장치 응답을 대체하지 않습니다.

처방·미션·OCR·적재·감사 로그·센서 이력은 hospital_web/backend/hospital.db에 저장합니다. 서버 재시작으로 중단된 작업은 FAILED_INTERRUPTED가 되며 자동 재개하지 않습니다.

문제가 생겼을 때

먼저 서버 로그와 아래 항목을 확인하세요. 재시작·초기화 전에 진행 중인 작업과 장치 상태를 확인합니다.

증상확인할 항목
웹 접속 불가통합 launch 로그, 서버 주소, hospital_web_port. 기본 포트는 8080입니다.
로봇 OFFLINEDoosan driver, arm_controller, ROS2 환경과 실제 로봇 연결.
영상·검출 없음RealSense, pyrealsense2, ROTOSY_VISION_MODEL. 검출 API의 model_loaded와 error를 봅니다.
집기 좌표 없음카메라 외부 보정, 깊이값, 마커, 서랍 보정. 검출 상자만으로 좌표가 준비되지는 않습니다.
작업 시작 실패처방 승인, 배송 요청, 장치 준비, 약품–서랍 매핑. Orchestrator의 phase와 error를 봅니다.
OCR 실패라벨 영상, Cloud Vision 인증, 처방. 실패 시 컨베이어로 분기하므로 이전 화면의 수동 복구 문구만 따라 재시도하지 마세요.
AMR 출발 실패두 적재 확인, 미션 상태, 목적지 좌표, Nav2 action server. AMR 시뮬레이션은 별도 launch가 필요합니다.
온습도 갱신 없음SENSOR_PORT, SENSOR_BAUD, SENSOR_ENABLED, 입력 시각. ROS2 초기화 실패 시 mock 값이 생길 수 있습니다.
